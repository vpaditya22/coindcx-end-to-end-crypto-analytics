# Contributing

1. Create a focused branch for each change.
2. Keep transformations deterministic where possible.
3. Add or update tests for metric logic and data-quality rules.
4. Do not commit raw extracts, credentials or generated database files.
5. State assumptions and units in documentation.
6. Run `pytest -q` before opening a pull request.
7. Use commit messages that describe the change and its purpose.
8. Never fabricate market data or business results to make a chart look stronger.
